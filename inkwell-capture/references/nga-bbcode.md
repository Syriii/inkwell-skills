# NGA 论坛 BBCode 标签清洗规则

NGA 使用自定义 BBCode（UBB 代码）进行排版。采集时需要对这些标签做**清洗或结构化转换**。

## 实际案例

从已采集帖子中提取的实际标签示例：

```
[b]Reply to [pid=875278218,47189694,1]Reply[/pid] Post by [uid=62276694]我是真的怕了[/uid] (2026-07-16 07:07)[/b]
```

```
[quote][pid=875278571,47189694,1]Reply[/pid] [b]Post by [uid=61345990]马提斯莫[/uid] (2026-07-16 07:17):[/b] [s:ac:哭笑]我大二痛经赶上体测，猛干一天...[/quote]
```

---

## 标签分类

### 一、排版类标签 — 应转换为 Markdown

| 标签 | NGA 语法 | Markdown 等价 | 说明 |
|------|---------|--------------|------|
| 粗体 | `[b]文字[/b]` | `**文字**` | |
| 斜体 | `[i]文字[/i]` | `*文字*` | NGA 限制 52 字符 |
| 下划线 | `[u]文字[/u]` | `<u>文字</u>` | Markdown 无原生支持 |
| 删除线 | `[del]文字[/del]` | `~~文字~~` | |
| 颜色 | `[color=red]文字[/color]` | `<span style="color:red">文字</span>` | 仅保留语义，可简化 |
| 字号 | `[size=150%]文字[/size]` | 忽略或 `<small>/<big>` | 归档为纯文本时可丢掉 |

**转换策略**：用正则 `\[b\](.*?)\[/b\]` → `**\1**` 逐层替换。优先处理排版类，因为它们常嵌套在其他标签内。

### 二、结构类标签 — 应转换为块级 Markdown

| 标签 | NGA 语法 | Markdown 等价 | 说明 |
|------|---------|--------------|------|
| 引用 | `[quote]内容[/quote]` | `> 内容` | "三板斧"之一，支持嵌套 |
| 带作者引用 | `[quote][pid=xxx]Reply[/pid] [b]Post by [uid=xxx]作者名[/uid]:[/b] 内容[/quote]` | `> **作者名**: 内容` | 常见于楼层回复 |
| 折叠 | `[collapse=标题]内容[/collapse]` | `<details><summary>标题</summary>内容</details>` | |
| 无标题折叠 | `[collapse]内容[/collapse]` | `<details><summary>点击展开</summary>内容</details>` | |
| 代码 | `[code]代码[/code]` | ` ``` ` 代码块 | |
| 列表 | `[list][*]项目1[*]项目2[/list]` | `- 项目1\n- 项目2` | |
| 标题 | `[h1]文字[/h1]` | `# 文字` | |

**注意**：`[quote]` 是最高频的嵌套标签，内层可能包含 `[b]`、`[pid]`、`[uid]`、`[s:]` 等。需要**先解析内层标签，再处理外层结构**。

### 三、元数据标签 — 应提取信息后移除

| 标签 | 格式 | 提取信息 | 处理方式 |
|------|------|---------|---------|
| 回复引用 | `[pid=875278218,47189694,1]Reply[/pid]` | PID, TID, 楼层 | 提取 PID，转为 `> 引用 #PID` 或直接去掉 |
| 用户提及 | `[uid=62276694]用户名[/uid]` | UID, 用户名 | 转为 `@用户名` |
| @提及 | `[@]用户名[/@]` | 用户名 | 转为 `@用户名` |
| 图片 | `[img]http://...[/img]` | 图片 URL | 已在 `_extract_nga_images()` 中处理 |
| 链接 | `[url]http://...[/url]` | URL | 转为 `[链接](url)` |
| 带文字链接 | `[url=http://...]文字[/url]` | URL + 文字 | 转为 `[文字](url)` |

### 四、表情标签 — 移除或保留文本

| 格式 | 示例 | 说明 |
|------|------|------|
| `[s:类别:表情名]` | `[s:ac:茶]` `[s:a2:中枪]` `[s:ac:哭笑]` `[s:ac:喷]` | 类别常见值: `ac`, `a2`, `pg` |
| `[s:类别:表情名?]` | `[s:a2:那个…]` | 部分表情名含中文或特殊字符 |

**处理策略**：
- **选项 A（去除）**：直接移除所有 `[s:...]` 标签，保留纯文本
- **选项 B（转义）**：保留表情名作为 `[表情:茶]` 注释
- **选项 C（保留）**：不做处理，保持原样

**建议**：选项 A（去除），因为表情标签在归档 Markdown 中没有等价表示，且影响可读性。

### 五、编辑标记

NGA 的编辑标记比较隐式：

| 标记 | 说明 | 处理 |
|------|------|------|
| 行尾 `改动` | 表示该回复被编辑过 | 去掉或在行尾加 `*(已编辑)*` |
| 行尾 `改动\n` | 同上，后跟换行 | 去掉 |
| 时间戳 `2026-07-16 07:07` | 回复/编辑时间 | 保留在回复头部 |

**注意**：`改动` 文本在 OP 正文中可能作为真正的文本内容出现（如"XX改动"），但在回复末尾出现时大概率是编辑标记。需要区分上下文：
- 出现在 body 末尾（最后几个字之一）→ 编辑标记，删除
- 出现在 body 中间 → 真实内容，保留

## 解析顺序（重要）

由于标签深度嵌套，应按以下顺序处理：

```
1. 提取 [img] URL（已完成 — _extract_nga_images）
2. 处理 [s:...] 表情标签（直接移除）
3. 处理叶子标签：[b], [i], [u], [del] → Markdown 内联
4. 处理元数据：[pid], [uid], [@] → 简化文本
5. 处理链接：[url] → Markdown 链接
6. 处理块级结构：[quote] → Markdown 引用, [collapse] → HTML details
7. 处理代码块：[code] → Markdown 代码块
8. 清理残留：未匹配的标签碎片
9. 去掉末尾 `改动` 编辑标记
```

**原则**：从内到外、从简单到复杂。内联标签先处理，块级标签后处理。

## 实现建议

### 方案 A：逐层正则替换（推荐起步）

在 `forum_scraper.py` 中添加 `_clean_nga_bbcode(text: str) -> str` 函数，按上述顺序逐步替换。

优点：简单可控，逐步迭代
缺点：深层嵌套（3+层）可能不完美

### 方案 B：递归解析器

构建 AST 并递归渲染。

优点：处理任意深度嵌套
缺点：开发成本高，且 NGA 实际嵌套通常不超过 3 层

### 建议

先实现方案 A（覆盖 95% 场景），方案 B 作为兜底仅在方案 A 结果异常时启用。
